# v1.1: multiple tuners and patch downgrade compatibility

Status: **v1.1.0-alpha.2 implements the multi-tuner runtime and UI**. It is a GitHub-only prerelease for isolated testing. Docker Hub's stable images and the existing production installation remain on the 1.0 line. Real Plex validation and the complete compatibility release gates below remain outstanding.

The implementation carries forward the v1.0.4 service/country/station matching and delayed-audio startup fixes. It adds the **USA - New York City** preset (150 channels) and **UK - London** preset (110 channels). See [the London selection and metadata audit](UK-LONDON.md).

## What alpha 2 implements

- Independently enabled, named HDHomeRun tuner profiles, with persistent device identity, country, market, time zone, and guide-location metadata.
- A profile-aware catalogue: channel numbers are unique within a tuner; channel IDs remain globally unique. Matching rules, policies, mappings, and rosters belong to their channel's tuner.
- Shared accounts, catalogue inputs, provider budgets, pacing, and playback resource limits. Viewers of the same channel share one primary/standby controller. Profiles do not multiply the global outgoing-stream limit.
- An expandable Output section for each tuner, with an enable checkbox, connection address, channels, roster details, and editing controls. Available presets can be added explicitly; lineup import/export and bulk operations target one tuner.
- Separate private listeners for additional devices. The primary tuner keeps its existing address. `ANTENNARR_TUNER_PORTS` reserves **9200–9207** by default; persistent profile offsets select ports within that range. The bounded range is bound at startup so profiles can be enabled without a restart; disabled profiles return 503 and unassigned slots return 404. Port exhaustion produces an error rather than silently reusing another device's address.
- Conservative matching across markets: country conflicts, different recognised services, and conflicting station/region evidence prevent automatic assignments. Unmarked shared brands cannot be guessed between US and UK tuners.

Both presets are present but disabled on a fresh installation. Enabling a tuner is explicit. Upgrades preserve the existing tuner's state and add London disabled once. Disabling retains the tuner's channels and rosters, blocks new tuning, and stops background recruitment for that tuner. Existing playback may finish. Removing a tuner is a separate operation; re-adding a preset creates a new identity and needs Plex setup again.

The port range is private tuner traffic, not an instruction to expose it to the internet. Docker deployments on a shared network need no host port publication. Other LAN clients need matching private host mappings and a reachable advertised address. The public administration proxy must not expose these tuner endpoints. See [installation](INSTALL.md) for the supported examples.

## Automatic upgrade to schema 9

Alpha 2 migrates the catalogue from schema 8 to **schema 9** before normal catalogue work begins. The transaction replaces the global channel-number constraint with `(profile_id, number)`, removes the obsolete assignment table and primary-only triggers, attaches existing channels to the primary profile, and validates foreign keys before committing the new version marker.

Existing channel IDs, aliases, station requirements, mappings, and rosters remain attached to the primary tuner. Existing accounts, credentials, configuration, and login remain in `/data`. Custom and intentionally empty lineups are preserved. A saved one-time marker prevents London from reappearing after it is deliberately removed. Reopening migrated data must not reset edits or duplicate profiles.

Use a disposable copy of appdata for this alpha. A 1.0 → 1.1 upgrade may change the internal format; returning to 1.0 requires a complete pre-upgrade manual backup. Two versions must never open the same data directory at the same time. Antennarr does not make an automatic backup for this upgrade.

The current tests exercise schema-8 custom data, repeat opening, profile isolation, disabled rosters, preset removal, and channel import/export. These tests are not yet a complete proof for every historical release, crash point, or old binary. Before stable 1.1.0, verify direct upgrades from every published stable 1.0 data format, including missing optional metadata and interrupted/failed migrations. Unknown or newer formats must fail clearly and must never trigger an empty replacement database.

## Real Plex release gate

Separate listener and HTTP tests establish endpoint isolation; they do not establish Plex playback or programme-guide behaviour. Before stable 1.1.0, record the tested Plex version and verify:

1. Two devices with distinct identities and independent US and UK guide selection.
2. Overlapping channel numbers, simultaneous viewers, and scheduled recordings across both devices.
3. Device, channel, and guide identity after restart, rename, disable/re-enable, and upgrade.
4. Correct affiliate or regional content during primary-to-standby failover.
5. Capacity accounting shared across both devices, including Plex's own recording scheduler.
6. Private network addresses, port publishing, and the primary stream-only fallback.

London postcode and guide suggestions remain unverified recommendations until that real Plex setup is exercised. A provider label or guide identifier cannot prove that the provider broadcasts the programme it claims.

## Stable 1.1 patch compatibility gate

The [versioning contract](VERSIONING.md) promises in-place downgrades **between stable patches in the same minor line**, starting at stable 1.1.0. It does not certify alpha/beta downgrades, 1.0 downgrades, or a 1.1 → 1.0 rollback.

Stable 1.1.0 must establish the baseline fixture and historical-binary harness. Every later stable 1.1 patch must be exercised against each earlier stable 1.1 patch on synthetic data, including older writers: settings saves, channel edits, cleanup, backup/restore, and re-upgrade. Preserve unfamiliar optional metadata and all user choices, credentials, identities, and station restrictions. A schema that can be opened is insufficient evidence that an older writer preserves its meaning.
